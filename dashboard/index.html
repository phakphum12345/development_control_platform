Emulators & VS Code

This page provides local commands and readiness guidance. A browser cannot inspect or launch processes on your computer; run these tasks from the repository in VS Code. Results from local checks are not automatically uploaded or treated as CI evidence.

Safety: emulator launch is explicit and local. The helper never installs SDKs, changes PATH, edits Android/iOS projects, or launches an app without an app-specific project being present.

Environment readiness

Check Python, Node/npm, VS Code CLI, Flutter, Android SDK tools and macOS simulator tooling.

python tools/dev_environment.py status

Connected devices

List Flutter devices and Android Debug Bridge devices. Missing SDKs or disconnected devices are reported as unavailable, not as a passing test.

python tools/dev_environment.py devices

Android virtual devices

List installed Android Virtual Devices. The tool will not create an AVD or download an image.

python tools/dev_environment.py avds

Launch a named AVD

Only launch a name returned by the AVD list. This starts the emulator process locally; it does not imply that an application is installed or tested.

python tools/dev_environment.py launch-avd --name YOUR_AVD_NAME

Static contract tests

Run repository contract and environment-helper tests with the Python interpreter configured for this workspace.

python -m unittest discover -s tests -v

Real-browser smoke tests

Requires Node.js, Playwright and Chromium. This validates dashboard browser behavior, not a native mobile app.

node tests/browser_smoke.mjs

VS Code integration

  • Open the repository root as the workspace.
  • Use Terminal → Run Task to run environment, test, browser-smoke and emulator discovery tasks.
  • Install recommended Python, PowerShell, Flutter/Dart and Playwright extensions when relevant.
  • Tasks use the current workspace and do not store credentials.

Commands are local-only. Emulator and test output must be reviewed before creating evidence.

Password Login

Client integration is fail-closed. Passwords are sent only to the same-origin authentication API over HTTPS; they are never stored in localStorage/sessionStorage. A real login requires a deployed backend that verifies passwords and issues Secure, HttpOnly, SameSite session cookies.
